# 第 1 章 时间序列数据

## 导言

学习时间序列模型之前，必须先回答一个更基础的问题：什么样的数据才是时间序列数据？在经济学和管理研究中，许多数据都带有时间标签，但并不是所有“带时间”的数据都适合直接当作时间序列来处理。全国月度 CPI、某只股票的日收盘价、某地区每小时电力负荷，是时间序列；31 个省份连续 20 年的 GDP、几百家企业逐年的财务指标，则是面板数据；某年一次住户调查中记录了“调查日期”，它仍然主要是截面数据。

这个区分不是形式主义。数据结构决定了我们该问什么问题、该画什么图、该用什么模型、该如何解释结果。如果把面板数据当成单一时间序列，可能会把地区差异误认为时间变化；如果把时间序列当成普通截面数据，又会忽略滞后、趋势、季节性、自相关和动态冲击。时间序列分析的第一步，不是立刻估计 ARMA、VAR 或 GARCH，而是看清楚数据的时间索引、观测单位和频率。

本章的目标是建立时间序列数据的基本数据观。我们先说明什么是时间序列数据，再比较它和带时间维度的面板数据；随后用实际经济例子展示几种常见数据结构；最后介绍在 R 中如何读入、解析、整理和保存时间序列数据，包括 `Date`、`POSIXct`、`ts`、`zoo`、`xts` 和 `tsibble` 等常用格式。

**本节小结。** 本章不是先讲模型，而是先讲数据。只有弄清楚时间索引、观测单位、频率和数据格式，后续的预测、因果识别和动态建模才有可靠基础。

------------------------------------------------------------------------

## 1 什么是时间序列数据

时间序列数据是按照时间顺序排列的一组观测值。最简单的时间序列只有一个变量，例如某国每月通货膨胀率：

```text
month       cpi_yoy
2023-01       2.1
2023-02       1.0
2023-03       0.7
2023-04       0.1
```

这里每一行对应一个月份，`cpi_yoy` 是这个月份的同比 CPI。时间不是普通解释变量，而是数据的索引。我们关心的不只是某个月 CPI 的数值，还关心这个数值与前后月份之间的关系：是否存在趋势，是否有季节性，是否出现突发冲击，冲击会持续多久。

时间序列也可以包含多个变量。例如，研究宏观经济运行时，我们可能同时观察 GDP、CPI、利率、汇率和货币供应量：

```text
quarter   gdp_growth   cpi_yoy   policy_rate   exchange_rate
2022 Q1       4.8        1.1         3.70           6.35
2022 Q2       0.4        2.3         3.70           6.70
2022 Q3       3.9        2.7         3.65           6.95
2022 Q4       2.9        1.8         3.65           6.98
```

这种数据仍然是时间序列，因为它只有一个观测对象：整个国民经济。多变量时间序列并不因为变量多就变成面板数据。判断数据结构时，关键不是变量个数，而是观测单位是否只有一个，时间是否构成主要索引。

时间序列数据通常具有以下几个特征。

第一，观测值有明确的时间顺序。2024 年 1 月在 2024 年 2 月之前，这个顺序不能随意打乱。普通回归中，我们有时可以交换样本行的顺序而不改变模型含义；在时间序列中，顺序本身就是信息。

第二，相邻观测值可能相关。今天的价格通常与昨天的价格有关，本月的销售额也会受上月销售额影响。这种相关性称为自相关或序列相关，它是时间序列模型的核心对象。

第三，时间序列可能存在趋势、季节性和周期。粮食价格可能有年度季节规律，宏观变量可能随经济发展长期上升，金融市场可能在危机时期出现波动聚集。

第四，时间序列具有频率。常见频率包括年度、季度、月度、周度、日度、小时、分钟和秒。频率不同，问题也不同。年度 GDP 适合研究长期增长，日度期货价格适合研究市场信息反应，小时电力负荷适合研究高频调度和短期预测。

**本节小结。** 时间序列数据的核心是“同一观测对象沿时间被重复观察”。时间顺序、自相关、趋势、季节性和频率，是时间序列区别于普通截面数据的基本特征。

## 2 时间序列数据与带时间的面板数据

许多经济数据同时包含个体和时间。比如我们有 31 个省份从 2000 年到 2024 年的农业总产值：

```text
province   year   agri_output   rural_income
北京       2020      118.2          31200
北京       2021      124.5          33303
河北       2020     3884.1          16467
河北       2021     4035.8          18179
河南       2020     5354.2          16108
河南       2021     5620.4          17533
```

这不是一个单纯的时间序列，而是面板数据。面板数据的每个观测由两个索引共同定义：个体 `i` 和时间 `t`。在上表中，个体是省份，时间是年份，观测值是某省某年的农业产值和农村居民收入。

时间序列和面板数据的核心区别可以概括为下表。

| 问题 | 时间序列数据 | 带时间的面板数据 |
| --- | --- | --- |
| 观测单位 | 一个对象 | 多个对象 |
| 索引 | 时间 `t` | 个体 `i` 与时间 `t` |
| 典型问题 | 未来走势、动态冲击、趋势与周期 | 个体差异、政策效应、异质性 |
| 例子 | 全国月度 CPI | 各省年度 CPI 或 GDP |
| 常见模型 | ARIMA、VAR、GARCH、状态空间模型 | 固定效应、随机效应、双向固定效应、动态面板 |
| 主要风险 | 忽略自相关、趋势和季节性 | 忽略个体异质性或组内相关 |

一个容易混淆的例子是“31 个省份的年度 GDP”。如果我们研究的是全国 GDP，并且每年只有一个全国数值，那么它是时间序列。如果我们保留每个省份每年的 GDP，那么它是面板数据。如果我们把各省 GDP 加总成全国 GDP，面板数据经过聚合后就变成了单一时间序列。

再看一个农业经济例子。假设我们有每个月全国玉米平均批发价：

```text
month       corn_price
2024-01       2550
2024-02       2520
2024-03       2495
```

这是时间序列。假设我们有不同批发市场每个月的玉米价格：

```text
market     month       corn_price
北京新发地  2024-01       2580
郑州市场    2024-01       2520
广州市场    2024-01       2640
北京新发地  2024-02       2550
郑州市场    2024-02       2490
广州市场    2024-02       2600
```

这是面板数据，因为同一个月份下有多个市场。同一个市场内部有时间序列变化，不同市场之间又有横截面差异。若研究“全国玉米价格下个月会不会上涨”，可以先聚合为全国时间序列；若研究“不同市场价格对运输成本变化的反应是否不同”，则应保留面板结构。

需要特别注意：面板数据中的每个个体都可以看作一条短时间序列，但整个数据集不等于一条长时间序列。不能把北京 2020、北京 2021、河北 2020、河北 2021 简单排成一列，然后当作四期时间序列来估计。这样会把“省份切换”误当成“时间推进”。

**本节小结。** 时间序列只有时间索引，面板数据同时有个体索引和时间索引。带时间标签的数据不一定是时间序列。判断数据结构时，先问三个问题：观测对象是谁？同一时点是否有多个对象？每一行由什么索引唯一确定？

## 3 几个实际例子

本节表格用于展示真实研究中常见的数据结构；除非特别说明，表中数值是课堂示意数据，不代表正式统计发布值。

### 3.1 宏观月度时间序列：CPI

月度 CPI 是典型的时间序列。它适合讨论通胀趋势、季节调整和短期预测。

```text
month       cpi_yoy
2024-01       0.3
2024-02       0.7
2024-03       0.1
2024-04       0.3
```

这类数据的时间频率是月度。常见问题包括：未来几个月 CPI 是否会继续回升？春节因素是否导致季节性波动？货币政策或食品价格冲击会不会影响通胀路径？

### 3.2 金融日度时间序列：期货收盘价

期货价格通常按交易日记录。由于周末和节假日没有交易，日期并不连续，但交易日顺序仍然明确。

```text
date         contract   close   volume
2024-03-01   M2405      3098    842130
2024-03-04   M2405      3112    901245
2024-03-05   M2405      3104    766811
```

如果只研究一个合约的收盘价，它是日度时间序列。如果同时保留多个合约，例如 M2405、M2409、M2501，每个合约都有自己的日度路径，那么数据具有面板或多重索引结构：合约 `contract` 与日期 `date` 共同确定一行。

### 3.3 农业与气象时间序列：降水和产量

农业经济研究常常把气象序列与产量、价格或种植面积联系起来。比如某县每日降水量：

```text
date         rain_mm
2024-06-01     0.0
2024-06-02    13.5
2024-06-03     4.2
```

如果只有一个县，这是一条日度时间序列。如果有多个县，则通常是县域面板。研究干旱冲击对玉米产量的影响时，面板结构往往非常重要，因为不同县的土壤、灌溉条件和种植结构不同。

### 3.4 高频时间戳数据：订单、交易和传感器

现实数据经常不是“每天一个值”或“每月一个值”，而是带有精确时间戳。例如电商订单、金融交易、物流轨迹和传感器记录：

```text
timestamp            order_id   value
2024-11-11 00:00:03  A10293     199
2024-11-11 00:00:05  A10294      59
2024-11-11 00:00:05  A10295     349
```

这种数据可能是不规则时间序列，因为观测并不按固定间隔出现。同一秒可能有多条记录，也可能长时间没有记录。建模前通常要先聚合，例如按分钟统计订单数、按小时计算销售额，或按日生成均值、最大值和波动率。

**本节小结。** 时间序列数据可以是低频宏观数据，也可以是高频交易和传感器数据。判断方法始终一样：确认观测单位、时间索引、频率，以及是否存在多个个体或多个键。

## 4 R 中时间变量的基本类型

R 中处理时间序列，首先要把时间列解析为正确的类型。最常用的是 `Date` 和 `POSIXct`。

`Date` 表示日期，不包含一天之内的具体时刻，适合日度、周度、月度或年度数据的日期索引。

```r
as.Date("2024-03-01")
```

`POSIXct` 表示日期加时间，适合小时、分钟、秒级数据。

```r
as.POSIXct("2024-03-01 09:30:00", tz = "Asia/Shanghai")
```

在实证数据中，时间经常以字符串形式出现。推荐使用 `lubridate` 解析，因为它对常见格式更友好。

```r
library(lubridate)

ymd("2024-03-01")
ymd_hms("2024-03-01 09:30:00", tz = "Asia/Shanghai")
dmy("01/03/2024")
ym("2024-03")
yq("2024 Q1")
```

时间戳处理时要注意时区。比如同一笔国际交易，服务器可能记录 UTC 时间，而研究者希望按北京时间统计日销售额。

```r
library(dplyr)
library(lubridate)

orders <- orders |>
  mutate(
    timestamp_utc = ymd_hms(timestamp, tz = "UTC"),
    timestamp_bj = with_tz(timestamp_utc, "Asia/Shanghai"),
    date_bj = as.Date(timestamp_bj)
  )
```

`with_tz()` 表示同一个真实时刻换成另一个时区显示；`force_tz()` 则表示把一个没有时区含义的本地时间强行解释为某个时区。二者含义不同，不能混用。

月度和季度数据还可以用 `zoo` 或 `tsibble` 提供的专门类型表示。

```r
library(zoo)
library(tsibble)

as.yearmon("2024-03")
as.yearqtr("2024 Q1")
yearmonth("2024 Mar")
yearquarter("2024 Q1")
```

**本节小结。** 在 R 中，时间列不能长期停留在字符串状态。日度数据通常用 `Date`，日内高频数据用 `POSIXct`，月度和季度数据可以使用 `yearmon`、`yearqtr`、`yearmonth` 或 `yearquarter`。

## 5 如何在 R 中读入时间序列数据

实际工作中，时间序列数据常见来源包括 CSV、Excel、数据库导出、API 下载和网页表格。本章先看最常见的 CSV 与 Excel。

### 5.1 读入 CSV

假设 CSV 文件 `cpi_monthly.csv` 内容如下：

```text
month,cpi_yoy
2023-01,2.1
2023-02,1.0
2023-03,0.7
```

可以用 `readr::read_csv()` 读入，并把月份转换为月度索引。

```r
library(readr)
library(dplyr)
library(tsibble)

cpi <- read_csv(
  "data/cpi_monthly.csv",
  col_types = cols(
    month = col_character(),
    cpi_yoy = col_double()
  )
) |>
  mutate(month = yearmonth(month)) |>
  arrange(month)

cpi
```

如果日期是标准年月日格式，可以直接指定为日期列。

```r
price <- read_csv(
  "data/soybean_price_daily.csv",
  col_types = cols(
    date = col_date(format = "%Y-%m-%d"),
    close = col_double(),
    volume = col_double()
  )
) |>
  arrange(date)
```

### 5.2 读入 Excel

许多课程作业和研究数据以 Excel 保存。可以用 `readxl::read_excel()` 读入。

```r
library(readxl)
library(dplyr)
library(lubridate)

corn <- read_excel("data/corn_price.xlsx", sheet = "daily") |>
  mutate(date = as.Date(date)) |>
  arrange(date)
```

如果 Excel 中的日期列被读成数字，往往是因为 Excel 用序列号保存日期。常见转换方式如下：

```r
corn <- corn |>
  mutate(date = as.Date(date, origin = "1899-12-30"))
```

### 5.3 处理时间戳

高频数据读入后，常常需要从时间戳中提取日期、小时、月份或季度。

```r
library(readr)
library(dplyr)
library(lubridate)

orders <- read_csv("data/orders.csv") |>
  mutate(
    timestamp = ymd_hms(timestamp, tz = "Asia/Shanghai"),
    date = as.Date(timestamp),
    hour = floor_date(timestamp, unit = "hour"),
    month = floor_date(timestamp, unit = "month")
  )
```

如果原始时间戳包含时区偏移，例如 `2024-03-01T09:30:00+08:00`，可以直接解析。

```r
trades <- read_csv("data/trades.csv") |>
  mutate(timestamp = ymd_hms(timestamp))
```

处理时间戳时，建议养成四个习惯：明确时区，按时间排序，检查重复时间，检查缺失时间。

```r
orders |>
  count(timestamp) |>
  filter(n > 1)

orders |>
  arrange(timestamp)
```

**本节小结。** 读入时间序列数据的关键不是把表格打开，而是让 R 正确认识时间。读入后应立即解析时间列、排序、检查重复与缺失，并确认频率是否符合研究问题。

## 6 R 中常见的时间序列格式

R 生态中没有唯一的时间序列数据格式。不同格式服务于不同任务。理解这些格式，有助于在建模、作图和数据整理之间顺畅切换。

### 6.1 普通数据框：data.frame 或 tibble

最通用的格式是普通表格，一列时间，一列或多列变量。

```r
library(tibble)

cpi_tbl <- tibble(
  month = as.Date(c("2024-01-01", "2024-02-01", "2024-03-01")),
  cpi_yoy = c(0.3, 0.7, 0.1)
)
```

这种格式最适合数据清洗、合并、画图和保存。它的优点是直观，能和 `dplyr`、`ggplot2` 等工具很好配合。缺点是它本身不记录频率，也不自动阻止重复时间。

### 6.2 base R 的 ts 对象

`ts` 是 R 自带的时间序列格式，适合规则频率的数据，例如月度、季度和年度。

```r
cpi_ts <- ts(
  cpi_tbl$cpi_yoy,
  start = c(2024, 1),
  frequency = 12
)

cpi_ts
```

`frequency = 12` 表示月度数据，`frequency = 4` 表示季度数据，`frequency = 1` 表示年度数据。`ts` 格式适合许多传统时间序列函数，例如 `arima()`、`decompose()` 和 `HoltWinters()`。

`ts` 的局限是时间索引较抽象。它知道“2024 年第 1 月”，但不保存真实日期列；对于不规则交易日数据和带多个个体的面板数据，`ts` 并不方便。

### 6.3 zoo 对象

`zoo` 对象可以使用任意有序时间索引，适合日期不完全规则的数据。

```r
library(zoo)

price_zoo <- zoo(
  x = price$close,
  order.by = price$date
)
```

对于周末和节假日不交易的金融数据，`zoo` 比 `ts` 更自然。它保留真实日期，并允许索引不等间隔。

### 6.4 xts 对象

`xts` 是建立在 `zoo` 基础上的扩展，常用于金融时间序列。

```r
library(xts)

price_xts <- xts(
  x = price$close,
  order.by = price$date
)
```

`xts` 适合股票、期货、汇率等日度或高频数据，支持按日期区间取子样本。

```r
price_xts["2024-03"]
price_xts["2024-03-01/2024-03-15"]
```

### 6.5 tsibble 对象

`tsibble` 是 tidyverts 体系中的时间序列表格格式，适合与 `dplyr` 风格的数据处理结合。它明确区分索引 `index` 和键 `key`。

单一时间序列：

```r
library(tsibble)

cpi_tsbl <- cpi |>
  as_tsibble(index = month)
```

多个个体的面板式时间序列：

```r
panel_tsbl <- province_data |>
  mutate(year = as.integer(year)) |>
  as_tsibble(key = province, index = year)
```

在 `tsibble` 中，`index` 是时间，`key` 是个体。这个设计特别适合提醒我们：如果数据中存在省份、企业、市场、合约等个体标识，就不能把所有行混成一条时间序列。

`tsibble` 还可以检查时间缺口。

```r
has_gaps(cpi_tsbl)
scan_gaps(cpi_tsbl)
```

如果确实需要补齐缺失时期，可以使用：

```r
cpi_tsbl |>
  fill_gaps()
```

**本节小结。** 普通表格适合清洗，`ts` 适合规则低频序列，`zoo` 和 `xts` 适合真实日期和金融数据，`tsibble` 适合 tidyverse 风格以及多条时间序列。格式选择应服务于研究问题，而不是为了追求某种“标准形式”。

## 7 建模前的数据检查

时间序列建模前，应至少完成以下检查。

第一，检查时间列是否成功解析。

```r
str(cpi)
summary(cpi$month)
```

第二，检查数据是否按时间排序。

```r
cpi |>
  arrange(month)
```

第三，检查重复时间。如果单一时间序列中同一个时间出现多行，必须弄清楚原因。

```r
cpi |>
  count(month) |>
  filter(n > 1)
```

第四，检查时间缺口。月度数据是否漏掉某个月？日度数据是否因为节假日而自然缺失？这两种情况的含义不同。

```r
cpi_tsbl <- cpi |>
  as_tsibble(index = month)

has_gaps(cpi_tsbl)
scan_gaps(cpi_tsbl)
```

第五，检查频率是否一致。不要把月度 CPI、季度 GDP 和日度利率直接放进同一个普通回归而不处理频率差异。常见做法包括聚合、插值、混频模型或只保留共同频率。

第六，画图。时间序列分析中，画图不是装饰，而是诊断。

```r
library(ggplot2)

ggplot(cpi, aes(x = month, y = cpi_yoy)) +
  geom_line() +
  labs(x = NULL, y = "CPI同比", title = "月度CPI时间序列")
```

画图时要观察：是否存在趋势，是否有季节性，是否有异常值，是否有结构突变，波动是否随时间变化。这些特征会直接影响后续模型选择。

**本节小结。** 建模前的数据检查至少包括类型、排序、重复、缺口、频率和图形诊断。许多时间序列错误并不是模型错了，而是时间索引在读入和整理阶段已经处理错了。

------------------------------------------------------------------------

## 8 从数据结构走向模型

理解时间序列数据结构后，才能自然进入模型。若序列有明显趋势，我们需要讨论平稳性和单位根；若序列有季节波动，需要考虑季节调整或季节模型；若序列的当前值与过去值相关，就会进入 AR、MA 和 ARMA 模型；若多个变量共同变化，就会进入 VAR；若变量之间存在长期均衡关系，就会进入协整和误差修正模型；若波动本身具有持续性，则需要 ARCH 和 GARCH。

本课程后续各章可以看作围绕同一个问题展开：在给定时间索引和数据结构之后，如何描述变量随时间变化的规律，并把这种规律用于预测、解释和政策分析。第一章的任务，就是确保我们知道自己手里的数据到底是什么。

**本节小结。** 时间序列模型不是从公式开始，而是从数据结构开始。先识别观测单位、时间索引和频率，再选择适合的模型，这是时间序列实证研究的基本顺序。

------------------------------------------------------------------------

## 本章小结

本章介绍了时间序列数据的基本概念。时间序列数据是同一观测对象沿时间重复观察形成的数据，核心特征包括时间顺序、自相关、趋势、季节性和频率。带时间标签的数据不一定是时间序列；当数据同时包含多个个体和多个时期时，它通常是面板数据。

本章还介绍了 R 中处理时间序列数据的基本方式。读入数据后，应尽早把时间列解析为 `Date`、`POSIXct` 或适合月度、季度数据的专门类型。普通数据框适合清洗和可视化，`ts` 适合规则低频序列，`zoo` 和 `xts` 适合真实日期和金融数据，`tsibble` 适合 tidyverse 风格和多条时间序列。

在实际研究中，数据整理往往比模型估计更容易出错。判断数据是时间序列、面板数据还是高频不规则数据，是后续建模的第一步。一个清楚的数据结构，能让预测问题更自然，也能让因果识别问题更严谨。
